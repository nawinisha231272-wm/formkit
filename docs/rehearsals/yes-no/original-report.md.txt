## Confusing, missing or wrong steps

1. **Nullable boolean adapter is undocumented.** Guide: “Replace src/index.ts with this Quantity field (a number input, with empty = null).” Also: “Zero is a valid number; null is empty.” This explains numbers but not tri-state booleans or true-only required validation. `booleanValue({empty:null})` failed compilation; `booleanValue()` rejected null in validation. Best attempt: supplied a structural adapter. Compiler feedback disclosed function-shaped `empty` and `jsonSchema`; spreading the boolean helper also caused a nullable `equals` mismatch. A standalone adapter passed all requested cases.

2. **Inline shell mode is missing.** Guide: “All imports, property helpers, defaults, events, theme classes and ARIA forwarding are included.” The guide demonstrates a numeric control but gives no shell-mode reference. Guessed `shell: "inline"`, then confirmed it with compilation, real layout measurements and screenshots. No shell markup was copied or reimplemented.

3. **Configurable text translation is unclear.** Guide: “Keep a typed English dictionary in the component and use it when t returns the unknown key, as message() demonstrates.” That example covers a fixed message, not editable captions that default to literal “Yes”/“No”. Best attempt: pass configured captions to `p.t`; unknown keys retain the configured English text. Default and edited captions work. The guide should state whether configurable captions are literal text, message keys, or both.

4. **Adapting the scaffold is necessary, but the advanced value contract is absent.** Guide: “After authoring a different control, update its value/interaction samples and metadata-editor cases in the generated tests.” The generated harness and editor helper worked as described. The nullable adapter's signatures and required semantics still had to be inferred through failed builds instead of a documented adapter contract.

CLI issue, separate from guide wording: `--help` prints “Usage: ourform create-component|create-theme|create-plugin name [--directory path] [--local-packages path]” but exits 1. My optional help invocation stopped an `&&` chain after a successful SDK build/pack. Retried generation separately. This was not a failed documented generation step.
