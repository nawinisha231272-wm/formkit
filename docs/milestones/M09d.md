# M09d — Extension and configuration

Status: **plan approved with owner amendments on 2026-10-23; implementation not started**.

Branch: `m09d-extension-configuration` · Depends on: M09c merged and reviewed.

Order: **M09b+ → M09c → M09d → M10a → M10b**. M09b approval remains a prerequisite to M09b+.

Gate: owner sign-off of this amended documentation, then extension/kit author evidence and owner delivery review.
M09d starts only after M09c; this decision does not approve or merge PR #15.

## Goal

Form.io-level component reuse and application configuration without executable form or kit JSON.
Compose immutable SDK descriptors; preserve the headless/model/view boundary and the SDK 0.x freeze.
This does not introduce class inheritance, a Form.io importer, a marketplace or remote module loading.

## Acceptance criteria

Every item requires a named test or reproducible command in progress.md. **None is passed by this plan.**

- [ ] Currency extends Number in **fewer than 25 meaningful lines**, including imports and the
      extension declaration (excluding blanks/comment-only lines; no handwritten builder code or
      concealed Currency-specific helper). It inherits number/null semantics, adds an editable
      currency property and wraps the base control. Every generated editor visibly updates preview.
      This is the SDK exercise; M10b still owns production currency parsing/rounding requirements.
- [ ] A multi-level field/layout chain inherits metadata, defaults, validators, shells and all
      applicable views without mutating ancestors. Depth 8 passes, depth 9/cycles fail; value-adapter
      replacement is explicit, typed and covered by adapter/validation/view conformance.
- [ ] A JSON-only kit adds **US phone** (Text preset plus a pre-registered named validator) and an
      object-scoped **Address** composite, depends on `ourform.builtins`, hides Password/Hidden,
      and locks Required on US phone. US phone declares a `reportColumn` string property with
      complete metadata, safe default and generated editor. Hosts/expressions can read it; changing
      it alone does not change rendering or submission validation. Trusted validators remain named
      bootstrap registrations outside the JSON.
- [ ] The identical kit bytes, plugin versions, exported form and submissions run in browser and
      Node with identical canonical data, ordered validation results and submission JSON Schema.
- [ ] Missing/incorrectly versioned/undeclared kit requirements fail with `missing-kit`; old
      plugin-only requirements stay compatible. Builder save records caret ranges from installed
      kit versions (`1.0.0` → `^1.0.0`); compatible patch/minor upgrades validate unchanged forms.
      Major changes to canonical values, validation or composite structure require a major kit bump;
      incompatible majors fail. Preserve npm-semver's narrower caret behavior for 0.x versions.
- [ ] Unknown bases/properties/references, conflicting kits, dependency/inheritance/composite cycles,
      incompatible engine/plugin ranges and unsafe/oversized JSON return the specified diagnostics
      without partial registration. Boundary and hostile-input tests cover every published limit.
- [ ] `overrideView("select", "react", view)` swaps React Select with **byte-identical form JSON**,
      unchanged value/validation semantics and no Angular/Element or other-instance change. Ordinary
      duplicate registration and conflicting overrides still fail explicitly.
- [ ] Generated edit dialogs merge inherited/new properties exactly once in the specified order.
      Defaults, wildcard/exact rules, host options and restrictive locks follow the precedence table;
      Add/Save/Cancel, Edit JSON, paste/duplicate, bulk edits and undo/redo cannot bypass locks.
- [ ] Host `editor.rules`/`palette.types` explicit reveals override kit/inherited hides. A kit can
      reveal another kit's hidden item only through a declared dependency. Unrelated conflicts fail;
      no reveal unlocks a property or bypasses slot eligibility or host component locks.
- [ ] All six data-only property kinds get metadata/default/type/bounds tests; unsafe names, `expr`
      kind and executable metadata are rejected. CLI validate matches engine codes/JSON Pointers
      for valid, malformed and hostile kits; create-kit output validates and offers schema autocomplete.
- [ ] Consumer-build size/network reports prove no-kit apps include/request no loader or meta-schema
      validator, kit-enabled apps meet the separately approved budget, shared chunks are counted once
      and the existing core/lazy budgets do not increase.
- [ ] Extended fields, layout reuse, kit components and the native replacement pass relevant host
      conformance, keyboard/focus checks and axe (no serious/critical issues), plus visuals in **Base,
      Bootstrap 4, Bootstrap 5, Tailwind and Material**. Strict CSP/offline behavior and per-engine/

- [ ] A **fresh Codex session with no implementation context** clones the verified SHA and builds

## Use in subsequent milestones

Kits use packaged registrations and the existing palette. They do not add Save as section, a user
template browser/gallery or section storage; those deferred authoring features remain after M10a.
The future **Save as reusable component** action will write kit presets in this same published format;
M09d provides the format/CLI, not that builder action.

M10a's new array scopes, row identity, grid/Wizard/Table slot/storage contracts need their own
headless models and SDK layouts. Do not derive an array from a scalar/object by changing scope.
Use `extendLayout` for presentation-only variants after those bases exist, and kits for fixed
Address/contact composites and row/page starter configurations in legal slots.

M10b should build Currency from Number and Phone from Text with `extendField`; ship US-phone and
currency-default variants through kits. Reuse Select for async Select only where its adapter and
inherited option-membership validation remain valid; otherwise define a new model. Use extension
for Autocomplete/Date/Time/DateTime only when their model/value
contracts actually match. File and Tags need their own nullable/object/array adapters and models;
use extensions/presets only for compatible variants after those bases exist. New components still
receive the full conformance suite; inheritance never substitutes for it.
